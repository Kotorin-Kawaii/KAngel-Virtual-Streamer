# 场次级公共总结

P21 的场次总结用于给主播提供极低密度的跨场背景。它不是观众个人记忆：不按账号、昵称或连接归属，也不参与关系分、改名感知、个人导出或个人记忆删除。

## 生命周期

排期的 `current_stream_start_time` 是稳定的 `stream_session_id`。排期进入直播时，服务端幂等创建一份 active 场次事实；排期结束后，服务端在同一 SQLite 事务中冻结事实并创建唯一的 `pending` 总结任务。应用重启后会继续扫描已结束的 active 场次，因此不会依赖 FastAPI 的启动或关闭事件来判断下播。

任务状态为 `pending`、`processing`、`completed` 或 `failed`。领取任务带租约，超时租约可恢复；失败按配置有限重试，只保存稳定错误码。任务和冻结事实只在终态且超过保留期后删除，默认保留 30 天。

## 数据边界

冻结输入仅包含排期时间与时区、主题、安全活动时间线、人格起止数值及有界房间聚合。它不会读取或保存原始弹幕、SC 正文、账号 ID、昵称、令牌、IP、个人长期记忆或模型隐藏推理。

总结输出是受限 JSON，包含摘要、情绪走向、房间氛围、已验证活动时间线及受限的公共话题字段。模型自由文本不会直接入库：后端只接受它选择已冻结的活动键与已验证公共话题，再由冻结的主题、活动、人格起止数值及房间聚合重新生成可读取的摘要、情绪走向和活动说明。公开前端和现有管理接口均不暴露冻结输入、任务错误或内部证据。

## AI 与回复边界

`SESSION_SUMMARY__AI_ENABLED` 默认是 `False`：系统只会冻结事实并创建任务，不会产生新的外部模型调用。显式启用后，总结消费者只在 SC 和普通回复的 AI 工作闸门空闲时领取任务，并不占用该闸门。

已完成总结只能作为当前活动连续、且当前弹幕字面触及该服务端活动 ID、类别、名称或对象时的低权重回复背景，位于直接弹幕、当前活动和观众个人证据之后；提示词明确要求它不能被当作个人记忆，也不能主动复述“上次直播”。当前实现不使用它改写活动事实或主题。

启用真实模型前，应在独立环境验证摘要质量、成本和供应商限流；这类验证不进入默认单元测试。

## 观测

受管理员边界保护的直播元信息统计只提供固定键计数：场次建档、冻结、恢复、任务领取/完成/失败/重试/让行、AI 消费器禁用、摘要注入命中和保留期删除。日志同样只描述事件与稳定错误码；统计键和日志均不以场次、主题、账号、昵称、原文或提示词作为标签。
