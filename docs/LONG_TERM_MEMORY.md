# 登录观众长期人物与话题记忆

目标不是让主播机械复述聊天记录，而是让她在有证据时自然接住同一位登录观众跨连接、跨直播的后续表达。（游客仍只使用直播间短期上下文。）

## 回复闭环

1. WebSocket 认证得到不可变 `account_id`、当前昵称和昵称版本。
2. 回复前读取该账号最近的对话片段与话题摘要。
3. 本地连续性分析判断当前弹幕属于首次话题、延续、转折、补充或切换。
4. 当前观众的个体证据优先于直播间全局短期弹幕进入回复提示词。
5. 模型完成回复后，保存“观众发言 → 主播回复 → 话题 → 时间 → 昵称版本”。
6. 活跃片段过多时，将较旧片段压缩为可追溯的抽取式话题摘要；过期或低价值归档按策略遗忘。

长期记忆写入失败不会中断本轮回复、人格状态提交或 WebSocket 广播。

## 话题连续性

连续性类型：

| 类型 | 示例 | 行为 |
|---|---|---|
| `new` | 第一条“今天上班好累” | 建立“上班”话题 |
| `continuation` | “然后呢”“所以怎么办” | 继承上一话题 |
| `contrast` | “但是有钱赚啊” | 继承话题并标记转折 |
| `supplement` | “而且同事也这样”“他也这样” | 补充上一话题 |
| `switch` | “换个话题，最近看了《BLAME!》” | 建立新话题 |

“他/她/它/这个/那件事”等指代只会被标记为承接上一片段中的人物或对象。系统不会擅自推断具体身份；提示词要求模型在证据不足时自然追问。

## 检索顺序与证据边界

账号内候选按以下信号排序：

- 当前话题精确匹配；
- 片段重要性；
- 时间衰减后的新近度；
- 过去是否被有效召回。

默认最多向回复提示词提供 6 条片段和 3 条摘要。提示词明确要求：

- 只能使用列出的片段和摘要；
- 不得补写未出现的姓名、经历、关系或细节；
- 不向观众说“数据库显示”或“根据记忆库”；
- 不提供历史昵称原文；
- 指代不清时询问，而不是猜测。

## 数据结构

`account_conversation_fragments` 保存：

- `account_id`、连接会话范围和弹幕 ID；
- 当时昵称及 `nickname_version`；
- 脱敏后的观众发言、主播回复和结构化回复；
- 话题、连续性类型和保守的指代说明；
- 情感、重要性、创建/访问/过期时间及归档状态。

`account_topic_memories` 保存由旧片段抽取合并的话题摘要、来源数量、重要性和生命周期。摘要只拼接真实片段中的观众发言与主播回复，不调用模型补写事实。

## 摘要、衰减和遗忘

- 活跃片段超过 `MEMORY__COMPACT_AFTER_FRAGMENTS` 后，保留最近片段并按话题归档旧片段。
- 检索新近度使用可配置半衰期，默认 45 天。
- 原始片段和摘要默认最多保留 180 天，不因被访问而无限续期。
- 归档原始片段设置数量上限，超限时优先保留重要且较新的证据。
- 用户清除或退出长期记忆时，关系、对话片段和话题摘要一并删除。

## 与其他数据的联动

- 熟悉度、信任、好感、连续话题和真实召回片段共同调节内部依恋与自信；陌生观众的一句话不会产生同等依恋变化。
- 主播成功接住延续、转折或补充话题时，关系熟悉度和信任获得小幅额外增长，所有变化仍受 0–1 边界限制。

## 配置

| 环境变量 | 默认值 | 说明 |
|---|---:|---|
| `MEMORY__RETENTION_DAYS` | `180` | 片段和摘要保留天数 |
| `MEMORY__RECENT_FRAGMENT_LIMIT` | `8` | 压缩后保留的活跃片段数 |
| `MEMORY__RETRIEVAL_LIMIT` | `6` | 单轮最多检索片段数 |
| `MEMORY__COMPACT_AFTER_FRAGMENTS` | `12` | 触发摘要压缩的活跃片段数 |
| `MEMORY__SUMMARY_MAX_CHARS` | `600` | 每个话题摘要最大字符数 |
| `MEMORY__IMPORTANCE_HALF_LIFE_DAYS` | `45` | 检索新近度半衰期 |
| `MEMORY__MAX_ARCHIVED_FRAGMENTS` | `100` | 每账号最多保留归档片段数 |

用户查询、导出、清除及退出接口见 [账号人物记忆与隐私接口](MEMORY_PRIVACY.md)。
